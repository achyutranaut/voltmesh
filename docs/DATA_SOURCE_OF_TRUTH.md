# VoltMesh — Data Source-of-Truth Map

This document establishes the single canonical architecture and authoritative source of truth for every data item across the VoltMesh Decentralized Energy Exchange platform.

---

## 1. Architectural Source-of-Truth Hierarchy

```
REAL SOURCE OF TRUTH
        ↓
Backend (TimescaleDB / Postgres / Redis)  ·  Blockchain (Anvil / Sepolia RPC)
        ↓
REST API / Ingest Gateway / Node RPC Contract Reads
        ↓
Frontend Client State (viem / wagmi / React Context)
        ↓
User Interface (Trading Terminal / Observability)
```

**Cardinal Rule**: There must NEVER be a secondary fake source of truth manufactured inside the frontend. If real runtime data is pending or unavailable, display an honest loading, pending, or empty state (`--`, `AWAITING AUCTION`, `PENDING SETTLEMENT`, `AWAITING EPOCH`). Simulated data must be explicitly isolated and labeled `[SIMULATED]`.

## 3. Data Integrity Invariant Rules

1. **No Silent Fallbacks to Convincing Numbers**:
   If a market has not cleared, `clearingPrice` must be `null` and rendered as `--` (or `AWAITING CLEARING`), NOT `₹4.40`.
2. **No Fake Hashes or Addresses**:
   Contract addresses must come exclusively from `apps/web/src/contracts/deployments.json`. Remove all hardcoded backup addresses.
3. **No Fabricated Blockchain History**:
   The activity panel and transaction modals must only record real cryptographic transactions confirmed by the RPC provider or signed via MetaMask.
4. **Transparent Simulation Demarcation**:
   When using local simulation generators (`MeterSimulator`, synthetic seed orders), the UI must display prominent `[SIMULATED]` badges so users and regulatory observers are never misled.
5. **No Static Health Indicators**:
   Service indicators must execute live liveness checks against RPC (`eth_blockNumber`) and service health endpoints (`/health`). If a service is offline, display `UNREACHABLE` / `OFFLINE` with amber/red status.
